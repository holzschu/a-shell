# Font regression

Use the real a-Shell `config` command on an isolated Simulator or device build. Do not run against a user's font collection: the scenario moves and restores its one supplied fixture. Use a clean `Documents/Fonts` containing only `Fixture.ttf`, and ensure the same face is not also installed system-wide.

The fixture is `JetBrainsMonoNerdFontMono-Regular.ttf` from Nerd Fonts v3.4.0, with PostScript name `JetBrainsMonoNFM-Regular` and SHA-256 `f01031f40e48dc29e1112e6b0b0450a2c6cd097f3f35cfff05c55cb311f8034c`. Download it from `https://raw.githubusercontent.com/ryanoasis/nerd-fonts/v3.4.0/patched-fonts/JetBrainsMono/Ligatures/Regular/JetBrainsMonoNerdFontMono-Regular.ttf`; it is test input, not an app resource.

Copy the fixture to `Documents/Fonts/Fixture.ttf` and this directory's `fonts.sh` to `Documents/fonts.sh`. Run `dash ~/Documents/fonts.sh` through the app terminal or command bridge. Require status 0 and a fresh `Documents/fonts-complete.txt` containing `complete`. The script verifies list/select, file-name resolution, invalid-name preservation, malformed-font diagnostics (CoreText domain, code, and affected URL), removal, and re-addition. On the unchanged app it fails because `--fonts` is unknown and the file is not registered.

After completion, `config --show` must report `JetBrainsMonoNFM-Regular 17.0 pt`. Relaunch the app and require the same result. In the app's Settings page, require Font = Custom, Custom font name = JetBrainsMonoNFM-Regular, Font size = 17. Change Font to Courier and size to 19, return to the same app process, and require `Courier 19.0 pt` from `config --show`. Change Custom font name to `Fixture.ttf` and choose Custom; returning to the app must render the supplied font. Reopen Settings after CLI changes to refresh its cached values.

Test a size-only edit separately: run `config -n Courier -s 17 -g --show` in the terminal and require `Courier 17.0 pt`. Record the app PID, reopen Settings, and change only Font size from 17 to 19. Return to the same app process and immediately run `config --show`; require `Courier 19.0 pt` before any relaunch or other configuration command. A saved preference of 19 or a successful UI automation run does not establish live synchronization. Then relaunch and independently require `Courier 19.0 pt` for persistence.

For coexistence, make the same face available independently of `Documents/Fonts` on an isolated Simulator: copy the fixture into the test app bundle and add `UIAppFonts = [Fixture.ttf]` to its built Info.plist before signing and installing. This is test setup only; do not add the font to the project or change a phone's profiles. With another copy at `Documents/Fonts/Fixture.ttf`, run `dash ~/Documents/fonts-existing.sh`. Require status 0, fresh `fonts-existing-status.txt` containing `0`, and `fonts-existing-complete.txt` containing `complete`. It checks listing and filename selection without duplicate-registration errors, then removes and restores the Documents copy while the independently available face remains selectable. This models coexistence, not installed-font picker entitlement behavior. Restore the Simulator app bundle before running `fonts.sh`.

Run `config -n picker -gp --show > ~/Documents/fonts-picked.txt`, select the local face, and require its exact name in the file. Repeat with a system font, select a non-regular face, and require its PostScript face name rather than the family. Cancel the picker and dismiss it by swiping; both must return to the shell, and the next ordinary command must succeed.

On a physical device, select an existing system-installed terminal font by name without relying on its monospace metadata. Capture the script's Powerline and icon line in light and dark colors using throwaway terminal text; inspect both images before sharing.
