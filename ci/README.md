# App native framework producer

`nice -n 15 bash ci/native-frameworks.sh PRODUCT` builds one of `helix`, `fd`, `fzf`, `navi`, `gitoxide`, `Ruff`, or `rg` on an Apple silicon Mac with Xcode 26.3, uv, and the toolchain pinned by that product's recipe. The Actions workflow provisions Rust 1.96.1, Rust 1.99.0 for Ruff, or Go 1.27.2 for fzf. Node needs Python 3.10-3.14 and npm. Compilation uses at most four jobs.

The producer calls the existing source recipes and patches. Each recipe verifies its source archive checksum; Cargo lockfiles and Go module checksums retain their dependency verification. A checksum-pinned public ios_system revision supplies the link dependency, independently of local framework caches. Each product contains exactly an arm64 device slice and one Simulator slice: arm64 for Node, universal arm64/x86_64 for the other products. Builds target iOS 14.0, or 16.0 for Node. Shipped artifacts use size optimization and symbol stripping; each product includes stripped and gzip byte counts. The final ZIP passes SHA256/SwiftPM, architecture, platform, minimum OS, command export and dependency-path checks before upload. Compilation and artifact checks do not establish app or phone behavior.

The Node producer refreshes `Resources/npm` and `Resources/node-fetch` and produces `node-npm.zip` and `node-fetch.zip`. Extract these into the app's `Resources/npm` and `Resources/node-fetch` respectively. JavaScript stays outside `node.xcframework`, matching the existing app packaging recipe. Intermediate Node frameworks stay under `.build`; the app's existing `xcfs/node.xcframework` is preserved.

Build Node with `nice -n 15 bash ci/native-frameworks.sh node SLICE`, where `SLICE` is `device` or `simulator`. Each invocation writes a framework tarball and SHA256 manifest under `.build/dist`; the device invocation also writes the two resource ZIPs. Transfer those outputs to `.build/node-slices`, then run `nice -n 15 bash ci/native-frameworks.sh node` to verify their checksums, assemble the xcframework and audit the final product. Actions runs the two slices in separate jobs, each limited to 360 minutes, followed by a 30-minute packaging job. The packaging job does not compile Node.

Pull requests and manual runs retain the eight framework ZIPs, audit reports, checksum manifests and release notes as Actions artifacts. Tags beginning with `native-` also trigger a build. Only tags in `holzschu/a-shell` can publish releases; auxiliary releases leave the repository's latest release unchanged. Existing release assets are never overwritten. Consumer URLs and checksums must come from a downloaded upstream release, after publication and verification.
