# App native framework producer

`nice -n 15 bash ci/native-frameworks.sh PRODUCT` builds one of `helix`, `fd`, `fzf`, `navi`, `gitoxide`, `Ruff`, `rg`, `codex`, or `Herdr` with Xcode, uv, and the toolchain pinned by the recipe. The Actions workflow uses Xcode 26.6 on Intel runners for Codex and Herdr, and Xcode 26.3 on Apple silicon for the other products. It provisions Rust 1.96.1 (or Ruff's own Rust pin), Go 1.27.2 for fzf, and Zig 0.16.0 for Herdr. Node needs Python 3.10-3.14 and npm. Compilation uses at most four jobs.

The producer calls the existing pinned source recipes and patches. A checksum-pinned public ios_system revision supplies the link dependency for dynamic frameworks. Codex uses a newer pin that exports its owned-stream API. Each archive contains arm64 device and arm64/x86_64 Simulator slices, except Node, which has an arm64-only Simulator slice. The deployment targets are iOS 26.2 for Codex, 16.0 for Node, 15.0 for Herdr's archive and 14.0 for the other products. Herdr's interactive worker pool still requires iOS 26. The final ZIP passes SHA256/SwiftPM, architecture, platform, minimum OS and command export checks. The audit checks dependency paths in dynamic frameworks and member load commands in static archives. These checks do not establish app or phone behavior.

To use the artifacts with Xcode, move any existing `codex/codex.xcframework` or `Herdr/Herdr.xcframework` out of the way before extracting. Unpack `codex.xcframework.zip` into `codex/` for the full app or `Herdr.xcframework.zip` into `Herdr/` for mini. Both recipes leave the ZIP and checksum manifest in `.build/dist`.

The Node producer refreshes `Resources/npm` and `Resources/node-fetch` and produces `node-npm.zip` and `node-fetch.zip`. Extract these into the app's `Resources/npm` and `Resources/node-fetch` respectively. JavaScript stays outside `node.xcframework`, matching the existing app packaging recipe. Intermediate Node frameworks stay under `.build`; the app's existing `xcfs/node.xcframework` is preserved.

Build Node with `nice -n 15 bash ci/native-frameworks.sh node SLICE`, where `SLICE` is `device` or `simulator`. Each invocation writes a framework tarball and SHA256 manifest under `.build/dist`; the device invocation also writes the two resource ZIPs. Transfer those outputs to `.build/node-slices`, then run `nice -n 15 bash ci/native-frameworks.sh node` to verify their checksums, assemble the xcframework and audit the final product. Actions runs the two slices in separate jobs, each limited to 360 minutes, followed by a 30-minute packaging job. The packaging job does not compile Node.

Pull requests and manual runs retain the framework ZIPs, audit reports, checksum manifests and release notes as Actions artifacts. To qualify only Codex and Herdr on a fork, select `embedded_only` in the manual run form. Tags beginning with `native-` also trigger a build. Only tags in `holzschu/a-shell` can publish releases; auxiliary releases leave the repository's latest release unchanged. Existing release assets are never overwritten. Consumer URLs and checksums must come from a downloaded upstream release, after publication and verification.
